# ERP 进销存管理系统 · 技术文档

> 项目类型：企业级进销存一体化管理系统（前后端分离）
> 技术形态：Maven 多模块单体应用 + SPA 前端
> 文档用途：简历项目说明 / 面试技术陈述

---

## 一、项目简介

一套面向中小型商贸 / 制造企业的 **进销存一体化管理系统**，覆盖「基础数据 → 采购 → 销售 → 零售 → 库存 → 结算 → 报表」全链路业务。

系统采用 **前后端分离** 架构：后端提供 RESTful 接口并统一鉴权与响应规范，前端为独立 SPA。核心业务围绕**单据流**运转——采购订单收货入库、销售订单发货出库、零售收银出货、库存调拨与盘点，每一类单据都有独立的主表 / 明细表，通过统一编号规则、库存变动入口与状态机串联。

### 核心业务模块

| 模块 | 主要功能 |
|---|---|
| 系统管理 | 用户、角色、部门、菜单、字典、操作日志、登录日志 |
| 基础数据 | 仓库、供应商、客户、品牌、物料分类、计量单位、商品 SKU |
| 采购管理 | 采购订单、采购收货、采购退货 |
| 销售管理 | 销售订单、销售出库、销售退货 |
| 零售管理 | 零售配置、零售出库、零售退货 |
| 库存管理 | 库存查询、库存流水、库存调整、库存盘点、库存调拨、库存预警、成本调整 |
| 结算管理 | 收支项目 + 供应商/客户 往来对账（各四单） |
| 报表统计 | 数据看板、采购统计、销售统计、库存报表、进销存汇总 |
| 商品中心 | SPU 商品、销售属性（颜色/尺码）、SKU 矩阵生成、一品多码 |

## 三、系统架构

### 1. 后端多模块划分

采用 **Maven 多模块** 拆分，按职责而非按技术分层，保证模块间依赖单向、无环：

```
erp-parent (父 POM，统一版本管理)
├── erp-common      公共能力：统一响应 R、异常体系、全局异常处理、
│                   操作日志切面、编号生成服务、实体基类
├── erp-system      系统域：用户/角色/菜单/部门/字典/日志 + Sa-Token 配置
├── erp-basedata    基础数据域：仓库/供应商/客户/物料/商品中心
├── erp-business    业务域：采购/销售/零售/库存/结算/报表
└── erp-web         接入层：全部 Controller、全局配置、定时任务
                    （唯一持有 Web 依赖的模块）
```

**设计要点：**

- **Controller 全部收敛在 `erp-web`**，业务模块只暴露 Service，避免业务层被 Web 语义污染。
- **实体基类下沉 `erp-common`**，`erp-system` / `erp-business` 共同继承，避免重复代码。
- **编号生成服务置于 `erp-common`**，采购、销售、零售、结算等各域共用同一套单据号体系。

### 2. 分层设计

```
Controller（参数校验 / 权限注解 / 响应封装）
    ↓
Service 接口 + Impl（事务边界 @Transactional，业务规则，状态流转）
    ↓
Mapper（MyBatis-Plus BaseMapper + LambdaQueryWrapper）
    ↓
MySQL
```

- **Entity / DTO / VO 三层分离**：Entity 对应表，VO 对应出参（列表页做字段裁剪与联表拼装），DTO 对应入参，杜绝实体直接出参导致的关联字段泄露。
- **统一响应 `R<T>`**：所有接口返回 `{ code, msg, data }`。
- **全局异常处理**：业务异常、业务校验异常统一捕获，映射为标准响应结构。

### 3. 前端架构

```
src/
├── api/          按模块划分的请求函数（axios 实例 + 拦截器）
├── components/   通用组件（下拉选择器、文件上传、导出按钮等）
├── layouts/      布局（侧边菜单、顶栏、面包屑，由后端菜单动态生成）
├── pages/        101 个业务页面，按模块分目录
├── store/        Zustand 全局状态（用户信息、权限、菜单）
└── utils/        request 封装、二进制下载、日期处理
```

- **动态路由 + 动态菜单**：登录后由后端返回该用户可见菜单树，前端据此生成侧边栏与路由，菜单与角色权限完全解耦。
- **按钮级权限**：页面内操作按钮按权限串控制显隐，后端再校验一次，前端隐藏只是体验优化，后端才是唯一可信边界。

## 四、关键技术实现

### 1. 权限体系：Sa-Token + RBAC

采用 **Sa-Token 1.46** 实现登录认证与接口鉴权，权限模型为「用户 → 角色 → 菜单（权限串）」三级结构。

- 全系统 **282 个 `@SaCheckPermission` 注解**覆盖到 Controller 方法粒度，实现接口级最小权限。
- 鉴权异常返回**真实 HTTP 401 / 403**，而非 200 包裹业务码，保证网关 / 前端拦截器 / 监控告警能正确识别。
- 登录拦截器统一注册，白名单接口（登录、验证码）显式放行，避免逐个接口加注解遗漏。

**权限缓存优化：** Sa-Token 的 `StpInterface` 每次鉴权都会被调用，若每次都查库则成为性能瓶颈。自定义 `SaPermissionCache` 一次性查询用户所有权限串写入 Redis，鉴权时直接读缓存；角色授权变更后主动 `evictUser` / `evictAll` 失效缓存，兼顾性能与实时性。

### 2. 单据编号规则引擎

单据号（采购单号、销售单号等）是业务主键的唯一标识，并发下重复会造成数据覆盖。设计了一套**表驱动的编号规则引擎**：

- `sys_code_rule` 表存储各单据的编号规则（前后缀、日期格式、流水位数、重置周期），共 **29 条规则**；
- 取号时对规则行执行 `SELECT ... FOR UPDATE` 行锁 + 最大流水号递增，**实测 20 并发取号零重号**；
- 支持按日 / 月 / 年重置流水，取号口径为**含已逻辑删除记录的全表最大值**，避免删除后重建撞唯一键；
- 该服务收敛在 `erp-common`，此前散落在各业务 Service 中的 28 处重复 `generateXxxCode()` 全部删除，编号规则统一可配置。

### 3. 库存变动三入口（数据一致性的核心设计）

库存是 ERP 最容易出错的地方。原设计所有库存变动都走同一个 `addStock` 方法，导致售价污染成本价、负库存等问题。重构为**语义清晰的三个入口**：

| 入口 | 适用场景 | 语义 |
|---|---|---|
| `addStock` | 采购入库等（数量 + 成本价同时变） | 数量与成本价同时更新 |
| `addStockKeepCost` | 退货、盘盈等（只回数量） | **不动成本价**，避免售价 / 单价覆盖 |
| `subStock` | 各类出库 | 扣减数量，出库成本按移动加权计算 |

并配合：

- **出库前按商品汇总校验库存**（`checkStockEnough`）：明细可能同一商品出现多行，必须先按 `product_id` 汇总再比对，逐条校验会漏判导致超卖；
- **成本调整只改价不改量**：直接 `UPDATE product_stock`，绝不经过 `addStock` / `subStock`，否则数量被二次变动。

**排查并修复的实际缺陷（均有实测用例覆盖）：**

| 缺陷 | 后果 | 修复 |
|---|---|---|
| 出库未校验库存 | 可扣出**负库存** | 三处出库入口补 `checkStockEnough` |
| 退货走 `addStock` 传售价 | **成本价被售价覆盖**，库存金额失真 | 改走 `addStockKeepCost` |
| 调整单传 `BigDecimal.ZERO` | 成本价归零、库存金额归零 | 改走 `addStockKeepCost` |
| 盘盈用盘点单单价覆盖成本 | 库存金额被改错 | 改走 `addStockKeepCost` |
| `getStatus() != 0` 直接比较 | `null` 时**拆箱 NPE**（37 处） | 统一用常量枚举 + `Objects.equals` |

### 4. 商品中心：SPU / SKU 双层模型

为支持「一品多规格」且**不影响存量单据**，引入 SPU + SKU 双层结构：

- **SPU** 承载商品公共信息（名称、品牌、分类），**SKU** 承载规格组合（颜色 × 尺码）与独立条码；
- SKU 矩阵：勾选销售属性组按**笛卡尔积**批量生成 SKU，幂等设计（只增不删，上限 200 条），避免重复点击产生脏数据；
- 销售属性采用**差异更新**而非删重建，防止属性 ID 变动导致历史 SKU 失联；
- **一品多码**：一个 SKU 挂多个条码，扫码时任一命中即可解析为同一商品。

**关键设计：保持 `base_material.id` 语义为 SKU ID**，使 13 张业务表、58 处 Java 代码、23 个前端文件**零改动**即可享受新模型——用「兼容式建模」代替「大规模重构」，把改造风险降到最低。

### 5. Excel 批量导入导出

基于 EasyExcel 实现主数据（物料 / 客户 / 供应商）的模板下载、批量导入、导出。

- **两趟校验**：第一趟全量解析校验（格式、必填、唯一性、关联有效性），第二趟才写库，任一行失败**整体回滚**，杜绝"导入一半"的脏数据；
- 大文件流式读取，避免 OOM；
- 下载二进制走独立工具封装（不进通用 request 封装，避免 responseType 污染）。

### 6. 操作日志与登录日志（AOP）

- 自定义 `LogAspect` 切面拦截写操作，记录**操作人、接口、参数、耗时、IP、结果**，敏感字段（密码等）脱敏；
- 登录按用户名密码 / 手机验证码 / 管理员三种分支处理，成功后回写 `last_login_time` / `last_login_ip`；
- 日志列表支持按操作人、类型、时间范围分页过滤。

### 7. 统一异常与响应规范

- 自定义异常体系（业务异常 / 参数校验异常）配合 `GlobalExceptionHandler`，把校验错误翻译成用户能看懂的提示；
- 未匹配 URL 返回规范 404 语义而非兜底 500；
- 统一响应包装 `R<T>`，前端 axios 拦截器统一处理登录失效跳转、错误提示。

## 七、技术亮点总结

1. **数据一致性设计**：将库存变动抽象为三入口（更新价 / 保留成本 / 扣减），从根上杜绝负库存与成本价污染，并用「按商品汇总后再校验」避免多行明细漏判。
2. **并发取号零重号**：表驱动编号规则 + `FOR UPDATE` 行锁 + 含删除记录的最大值口径，20 并发实测无重号。
3. **性能优化有据**：自建权限缓存替代每次鉴权查库，授权变更主动失效，兼顾性能与权限实时性。
4. **低风险架构演进**：SPU/SKU 改造通过保持存量字段语义不变，实现 13 张业务表、58 处后端代码、23 个前端文件**零改动**升级。
5. **横切能力复用**：编号生成、Excel 导入导出、操作日志三套能力下沉 `erp-common`，业务模块开箱即用。
6. **规范落地**：统一响应 / 异常 / 审计字段 / 幂等 SQL 脚本，全项目一致执行。
