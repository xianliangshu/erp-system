# 库存体系补齐方案（评审稿）

> 第三批开发计划。目标：把「库存管理」目录从"能记账"补齐到"能管货"。
> 参照 xingyun（星云 ERP）`xingyun-sc` 模块设计，按本项目命名与约定改写。
> 编写日期：2026-10-03

## 一、现状实测

### 1.1 已有能力（不动）

| 菜单 | 权限串 | 落点 |
|---|---|---|
| 库存查询 | `business:stock:query` | `StockController` / `product_stock` |
| 库存流水 | `business:stock:log` | `ProductStockLogController` |

### 1.2 缺口（本批要补的 5 项）

| # | 功能 | xingyun 权限串 | 本项目现状 |
|---|---|---|---|
| 1 | **盘点参数设置** | `stock:take:config:*` | 无。盘点行为（显示库存、是否自动调账、超时作废）全硬编码 |
| 2 | **预先盘点单** | `stock:take:pre:*` | 无。只有一次性盘点单 |
| 3 | **盘点任务** | `stock:take:plan:*` | 无。无法按"全场/分类/品牌/单品"批量发起盘点并快照库存 |

### 1.3 数据量（决定可彻底重构）

`product_stock` **1 行**、`product_stock_log` **2 行**、`stock_check*` **0 行**。
⇒ 全部为纯新增，**不涉及存量数据迁移**，回滚只需 `DROP` 新表。

## 二、数据模型设计

### 2.0 总览

```
库存管理
├─ (已有) 库存查询 / 库存流水
├─ (新增) 库存预警        stock_warning                    ← 仓库 × 商品 的上下限
├─ (已有) 库存调整        ─ 调整原因 / 调整单（改数量）
├─ (新增) 库存成本调整    stock_cost_adjust_sheet(+detail)  ← 只改成本价
├─ (新增) 盘点任务        take_stock_plan(+detail)         ← 发起盘点 + 库存快照
├─ (新增) 预先盘点单      pre_take_stock_sheet(+detail)    ← 初盘/复盘/抽盘记录
├─ (已有) 库存盘点        stock_check(+detail)  ← 补 plan_id / pre_sheet_id 关联
└─ (新增) 盘点参数设置    take_stock_config                ← 单行配置
```

### 2.1 `take_stock_config` 盘点参数（单行表）

对齐 xingyun `tbl_take_stock_config` 的 5 个语义字段，**用 `id=1` 固定单行**。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | 固定 1 |
| `show_product` | tinyint | 盘点单关联任务后，是否带出任务中的商品明细 |
| `show_stock` | tinyint | 是否显示任务创建时的**系统库存快照** |
| `auto_change_stock` | tinyint | 差异生成时是否**自动**调整库存（否则需人工审核） |
| `allow_change_num` | tinyint | 盘点数量是否允许手工修改 |
| `cancel_hours` | int | 任务创建后多少小时未完成自动作废（默认 24） |
| + 基类公共列 | | `create_time/update_time/create_by/update_by/deleted` |

种子数据：`(1, 1, 1, 0, 1, 24)` —— 带出商品、显示快照、**不自动调账**（安全默认）、允许改数、24h 作废。

### 2.2 `take_stock_plan` / `take_stock_plan_detail` 盘点任务

**主表**

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `code` | varchar(32) UK | 编号规则 `STOCK_TAKE_PLAN` → `PD202610030001` |
| `sc_id` | bigint | 仓库 |
| `take_type` | tinyint | **0 全场 / 1 单品 / 2 分类 / 3 品牌** |
| `biz_id` | varchar(500) | 盘点范围 ID 串（逗号分隔：分类 ID / 品牌 ID / 商品 ID） |
| `take_status` | tinyint | **0 任务生成 / 6 差异已生成 / 9 盘点完成 / 12 已作废** |
| `description` | varchar(500) | 备注 |
| + 基类公共列 | | |

**明细**（快照语义）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` / `plan_id` / `product_id` | bigint | |
| `stock_num` | decimal(16,4) | **创建任务时的系统库存快照**（关键：盘点期间库存变动不影响比对的基准） |
| `ori_take_num` | decimal(16,4) | 盘点数量（原始录入） |
| `take_num` | decimal(16,4) | 修正后盘点数量 |
| `total_out_num` / `total_in_num` | decimal(16,4) | 盘点期间该商品的出/入库累计（用于"动碰盘点"） |
| `description` / `order_no` | | |

> 无数据库唯一键（`plan_id + product_id` 只在应用层去重）—— 参照 SKU 改造的教训：
> 带逻辑删除的表上加唯一键，删后重建必撞键。

### 2.3 `pre_take_stock_sheet` / `pre_take_stock_sheet_detail` 预先盘点单

业务含义：**正式盘点单之前的分次清点记录**（初盘 → 复盘 → 抽盘），用于交叉校验。

**主表**：`id / code / sc_id / take_status(0 初盘 / 1 复盘 / 2 抽盘) / description` + 基类
**明细**：`id / sheet_id / product_id / first_num / second_num / rand_num / order_no`

> 预先盘点单**不产生任何库存变动**，纯记录。

### 2.4 `stock_warning` 库存预警

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | bigint PK | |
| `sc_id` | bigint | 仓库（0 = 全仓通用） |
| `product_id` | bigint | 商品 = SKU（沿用 `base_material.id`） |
| `max_limit` | decimal(16,4) | 预警上限，NULL = 不管上限 |
| `min_limit` | decimal(16,4) | 预警下限，NULL = 不管下限 |
| `status` | tinyint | 1 启用 / 0 停用 |
| + 基类公共列 | | |

**触发方式（本批采用"实时查询"，零侵入）**：
新增 `GET /stock/warning/hit-list`，SQL 直接 `JOIN product_stock` 比对上下限，返回超限明细。
**不改动** `IProductStockService` 的任何出入库入口 ⇒ 老链路零回归风险，也不需要定时任务。

> 对比被否决的方案：在 `addStock/subStock/addStockKeepCost` 里挂钩子写预警记录表。
> 优点是能留痕，缺点是要动 12 个库存调用点、并引入"预警记录"第 7 张表。留到下批（配合打印/通知）再做。

### 2.5 `stock_cost_adjust_sheet` / `_detail` 库存成本调整

业务含义：**只改成本价、不改数量**。用于成本录错、批次成本重估。
和现有「库存调整单」的分工：调整单改数量，成本调整单改价格。

**主表**：`id / code / sc_id / product_num(调价品种数) / diff_amount(调价差额合计) / status / description / approve_by / approve_time / refuse_reason` + 基类

**明细**：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` / `sheet_id` / `product_id` | bigint | |
| `stock_num` | decimal(16,4) | 当前库存数量（算差额用） |
| `purchase_price` | decimal(16,4) | 档案采购价（参考） |
| `ori_price` | decimal(16,4) | **调整前**成本价（`product_stock.tax_price`） |
| `price` | decimal(16,4) | **调整后**成本价 |
| `diff_amount` | decimal(16,4) | `(price - ori_price) × stock_num` |
| `description` / `order_no` | | |

**审核通过时的库存写入**（唯一会改库存数据的地方）：

```
UPDATE product_stock
   SET tax_price  = :price,
       tax_amount = :price * stock_num,
       update_time = NOW()
 WHERE sc_id = :scId AND product_id = :productId AND deleted = 0
```

- ⛔ **不走 `addStock`**：数量没变，走库存入口会把 `stock_num` 加一遍。
- 差额落 `product_stock_log`（新增业务类型 `COST_ADJUST`），保证流水可追溯。

### 2.6 现有 `stock_check` 补 2 列

| 列 | 类型 | 说明 |
|---|---|---|
| `plan_id` | bigint NULL | 关联盘点任务（老数据为 NULL） |
| `pre_sheet_id` | bigint NULL | 关联预先盘点单（老数据为 NULL） |

两列**全部可空** ⇒ 现有盘点单代码、SQL 完全不受影响。

## 四、菜单与权限

挂在「库存管理」(`id=1`, `M000200`) 下，`code` 延续 `M0002xx` 段（207 起，未占用）。

| 菜单 | code | path | permission |
|---|---|---|---|
| 库存预警 | M000207 | /stock/warning | `stock:warning:query` |
| 库存成本调整 | M000208 | /stock/adjust/cost | `stock:adjust:cost:query` |
| 盘点任务 | M000209 | /stock/take/plan | `stock:take:plan:query` |
| 预先盘点单 | M000210 | /stock/take/pre | `stock:take:pre:query` |
| 盘点参数设置 | M000211 | /stock/take/config | `stock:take:config:query` |

按钮级权限（`menu_type=2`）：每个页面按需挂 `:add` `:modify` `:delete` `:approve` `:export`。

> 菜单只**新增**，不改动任何既有行的 `code/path/permission` ⇒ 不会撞"注解串必须已存在"的铁律，
> 也不需要给存量角色重新授权（新菜单默认授权超管 R000001，其余角色按需勾选）。

⚠️ **顺序硬约束**：新增权限串**先执行菜单 SQL 入库 → 清 `erp:auth:*` 缓存 → 再发后端 JAR**。
否则非超管调新接口永远 403。

## 七、验收用例（S7）

1. 盘点参数保存后重进页面能回显；
2. 库存预警：库存 90、下限设 100 → 命中列表含该商品；下限设 50 → 不命中；
3. 成本调整单：成本价 110 → 调整为 150，数量 90 不变，`tax_amount` 由 9900 → 13500，流水新增一条 `COST_ADJUST`；
4. 成本调整单拒绝：填 `refuse_reason`，库存**不变**；
5. 预先盘点单：初盘/复盘/抽盘三个数量独立保存；
6. 盘点任务 - 全场：生成任务明细条数 = 当前有库存的商品数，`stock_num` = 创建时快照；
7. 盘点任务 - 分类：只生成该分类下商品；
8. 盘点任务作废后不能再生成差异；
9. 盘点单关联任务：选任务后带出商品明细（受 `show_product` 控制）；
10. **老链路冒烟**：不关联任何任务的老盘点单流程、采购入库 → 销售出库 → 库存查询，行为与改造前完全一致；
11. 权限：采购经理访问成本调整接口 → 403；超管 → 200。

## 八、风险与回滚

| 风险 | 应对 |
|---|---|
| 成本调整单写库存价格写错 | 必须**审核通过**才写库；写前二次校验 `stock_num` 与当前库存一致，不一致则拒绝 |
| 盘点任务快照过期 | `cancel_hours` 超时由 `@Scheduled` 标记作废；差异生成前校验状态 |
| 新增表名与现有冲突 | 已核对：8 个表名在 `erp-data` 中**均不存在** |
| 回滚 | 新表/新列老代码不感知，出问题 `DROP TABLE` + `DROP COLUMN` 即可，**无存量数据需要回滚** |

## 九、待确认事项

1. **是否本轮一并做「库位（仓位商品）」？**
   xingyun 的 `StockCell` + `StockCellProduct`（仓库 → 库位 → 商品）需要把 `product_stock` 的
   维度从 `(sc_id, product_id)` 扩成 `(sc_id, cell_id, product_id)`，**会动 13 张表里所有库存读写**，
   风险等级与本批其余 5 项不在一个量级。**建议单独作为第四批**。

2. **盘点任务自动作废是否引入 `@Scheduled`？**（项目当前无 Quartz，用 Spring 内置调度最轻）
   → **已拍板：引入**。`ErpApplication` 加 `@EnableScheduling`，`TakeStockPlanExpireJob` 每 10 分钟扫一次
   （cron `0 0/10 * * * ?`），把 `cancel_hours` 超时且仍为「任务生成」的任务置为「已作废」。

3. **库存预警是否需要「导入导出」？**（xingyun 有 `stock:warning:import`，本批建议先不做）

4. **成本调整单是否需要「批量按档案采购价重估」入口？**（先做手工逐行，批量后置）

### 10.3 与原方案的 3 处修正

1. **成本调整单状态码改为 0/1/2**（原写 0/3/6 对齐 xingyun）—— 本仓库 `StockAdjustSheetStatus`
   已是 0/1/2，跟随既成约定，前端处理逻辑可直接复用。
2. **新增 `GET /stock/adjust/cost/stock-info`** —— 制单页要展示「当前库存 / 当前成本价」，原打算复用
   `/business/stock/page`，但那是 `business:stock:query` 权限，成本调整的目标角色不一定有；
   改为在成本调整自己的权限域内提供查询端点。
3. **`stock_warning` 显式不加唯一键** —— 原设计提过 `uk(sc_id, product_id)`，落地时按 SKU 改造的教训去掉：
   唯一键不含 `deleted`，逻辑删除后重建必撞。判重移到 Service 层（实测重复新增被友好拦截）。

**第二段设计要点**

1. 🔴 **盘点任务自身不改库存**：差异汇成一张 `stock_check`（回填 `plan_id`），复用盘点单已有的审核流程 ——
   不另写一套调账逻辑。`autoChangeStock=1` 时生成差异后顺带调 `approveCheck`。
2. 🔴 **品牌盘点要经 SPU 中转**：`base_material` 没有 `brand_id`，只有 `base_spu` 有 ⇒
   品牌 → `base_spu.brand_id` → SKU（`base_material.spu_id`）。
3. **「全场」上限 2000 条明细**：防误选把库刷爆（同 SKU 矩阵 200 上限的思路）。
4. **带出商品时「账面数量」取任务快照**，而不是「现在」的库存 —— 快照才是这次盘点的比对基准。
5. `allowChangeNum=0` 时盘点数量强制回退为快照值。
6. `stock_check` 的差异单成本价：优先取 `product_stock.tax_price`，无库存记录时退回商品档案采购价，
   避免差异金额恒为 0。

### 10.6 第二段踩坑（重要）

1. 🔴 **`@RequestBody Map<String,Object>` 接收明细数组必 500**：Jackson 把 `details` 反序列化成
   `List<LinkedHashMap>`，Service 里 `for (TakeStockPlanDetail d : details)` 抛 `ClassCastException`
   （泛型擦除让强制转换编译期不报错）。必须用**强类型 DTO**（已补 `TakeStockNumsParam`）。
2. **新增 Controller 漏 `import java.util.List;` 时 `compile` 可能不暴露，`package` 才炸** ——
   改完 Controller 直接跑 `mvn package`，别只跑 `compile`。
3. **`vite build` 清 `dist` 会被沙箱 safe-delete 拦（`spawnSync ... ETIMEDOUT`）**：
   先把 `dist` `mv` 改名挪开再构建。
4. **`vite preview` 只监听 `[::1]`**：CDP 脚本里必须用 `http://localhost:3001`，用 `127.0.0.1` 连不上。
5. **`nohup java ... &` 起的进程会被工具回收**（日志停在半途、端口不监听）：
   长驻服务必须用工具自带的后台执行模式。
